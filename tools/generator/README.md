# ghdemogen — генератор тестовых данных для GitHub (ЛР 2.0)

Замена Azure DevOps Demo Generator: по шаблону `templates/parts-unlimited.json` заполняет
организацию GitHub данными для ЛР 2.1, 2.2 и 3.

| Создаётся | Сколько |
| --- | --- |
| Типы задач Epic, Feature, PBI, Task, Bug | недостающие (по умолчанию в организации есть Task, Bug, Feature) |
| Метки | web, api, mobile, security, bug |
| Вехи | «Релиз 1.0» (конец Sprint 3), «Релиз 1.1» (конец Sprint 5) |
| Проект GitHub Projects | «Unlimited Parts» (или дополняется существующий с тем же названием) |
| Поля проекта | Status (Новое, Утверждено, В работе (Committed), Готово), Спринт (6 итераций по 14 дней, Sprint 1 — прошедший, Sprint 2 — текущий), Область, Оценка, Остаток, Активность, Начало, Окончание |
| Задачи | 37: 4 эпика, 8 функций, 14 PBI, 3 ошибки, 8 задач с иерархией через sub-issues |

## Требования

* Python 3.9 или новее (сторонние пакеты не нужны, сборка не требуется).
* Организация GitHub, где вы владелец (Owner).
* Personal Access Token (classic) со сроком действия 7 дней и областями `repo`, `project`, `admin:org`.
  Выпуск: **Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token**.
  Короткий срок жизни — та же мера безопасности, что и в методичке для PAT Azure DevOps.

## Запуск

```bash
# Windows PowerShell:  $env:GITHUB_TOKEN = "<токен>"
export GITHUB_TOKEN=<токен>
python ghdemogen.py            # диалог: шаблон → PAT → организация → репозиторий → проект
```

Без вопросов:

```bash
python ghdemogen.py --owner <организация> --repo parts-unlimited --project "Unlimited Parts" --yes
```

Посмотреть, что будет создано, ничего не создавая:

```bash
python ghdemogen.py --dry-run --owner <организация>
```

Генерация занимает 2–4 минуты: между запросами, создающими данные, выдерживается пауза 1 с
(параметр `--delay`), чтобы не превысить ограничения GitHub на частоту создания контента.
Итог пишется в файл `ghdemogen-<организация>-<репозиторий>.json`.

После запуска откройте проект → **Settings → Workflows** и проверьте, что правило «Item closed»
выставляет состояние «Готово» (генератор заменил стандартные значения поля Status).

Повторный запуск безопасен: генератор дополнит существующий проект недостающими полями, а задачи,
созданные прошлым (в том числе прерванным) запуском, найдёт по служебной отметке в описании и
дополнит, не создавая дубликатов. Если в проекте включено правило **Auto-add to project**, GitHub
может добавить задачу в проект одновременно со скриптом — генератор это учитывает и берёт уже
добавленный элемент.
